# テストカバレッジ計測・保存

これは実装フローの⑤番目の手順です。④で承認済みのコードに対してテストカバレッジを計測し、結果を保存します。

## 入力

`$ARGUMENTS` を解釈してください。想定される内容:

- 1つ目: 実装先プロジェクトのルートパス
- 2つ目（省略可）: 対象パッケージ・ディレクトリ（省略時は`./...`相当、プロジェクト全体）
- 3つ目（省略可）: 規約ディレクトリのパス（カバレッジ基準が規約で定められている場合に参照する）

## 作業内容

1. 規約ディレクトリが渡されている場合、カバレッジ基準（目標数値等）が定められていないか確認する。定めがなければ「基準なし。数値のみ記録」として扱う
2. テストを実行し、カバレッジを計測する（Goの場合の例: `go test ./... -coverprofile=coverage.out` → `go tool cover -func=coverage.out`）
3. パッケージ／ファイル単位のカバレッジ率を確認する
4. カバレッジ結果を保存する

## 出力

実装先プロジェクト内に以下を保存してください（プロジェクトの慣習があればそれに合わせる。特になければ新規作成する）。

- 生カバレッジデータ（例: `coverage.out`。既存の`.gitignore`運用に合わせるか確認する）
- `〇〇機能_カバレッジ報告.md`（実装先プロジェクトのルート、または③実装仕様書と同じ場所）

```markdown
# 〇〇機能 カバレッジ報告

- 計測日: {日付}
- 計測コマンド: {実行したコマンド}

## サマリー
| パッケージ / ファイル | カバレッジ率 |
|-|-|

## 基準との比較
規約に基準がある場合はその基準値との比較を記載。ない場合は「基準なし。参考数値として記録」と明記。

## カバレッジが低い箇所（あれば）
| 対象 | カバレッジ率 | 未カバー内容の概要 |
|-|-|-|
```

## 注意事項

- カバレッジ数値の良し悪しの最終判定はここでは行わず（規約に明確な基準がある場合を除く）、次の `/impl:quality-review` に委ねてください
- カバレッジ計測のためにテスト内容を書き換えない（テストコードの修正が必要な場合は `/impl:code` に戻る）

## 完了時

カバレッジ報告を保存したら、次は `/impl:quality-review` で独立したレビュー用サブエージェントによる品質報告書作成に進む旨をユーザーに伝えてください。
