# 実行計画書 セルフチェック（AI + 目視）

これは実装フローの②番目の手順です。①で作成した実行計画書を、③コード生成に進める前に検証します。

## 入力

`$ARGUMENTS` を解釈してください。想定される内容:

- 1つ目: `/impl:plan` で作成した「〇〇機能_実行計画書.md」のパス
- 2つ目: 対象の「〇〇機能_Go実装仕様書」（③）のパス
- 3つ目（省略可）: 規約ディレクトリのパス

## 作業内容（AIによる自動チェック）

以下を機械的に照合し、チェックリスト形式で結果を出してください。

1. **網羅性**: ③「2. ディレクトリ構成」に列挙された全ファイルが、実行計画書「2. 作成ファイル一覧・順序」に含まれているか（過不足があれば具体的に指摘する）
2. **テスト網羅性**: ③「16. テストケース設計」の全テストケースが、実行計画書「4. テストケース一覧」に反映されているか
3. **整合性**: 実行計画書の実装要点が③・規約と矛盾していないか
4. **規約遵守**: 実行計画書の方針が規約（アーキテクチャ／コーディング／Gorm／Gin）に反していないか
5. **未確定事項の明記**: ③に根拠のない判断が「未確定事項」として明記されているか（こっそり断定されていないか）

## 出力

実行計画書の末尾に以下のセクションを追記してください（ファイルを直接編集する）。

```markdown
## セルフチェック結果（AI・実施日: {日付}）

| 観点 | 結果 | 指摘事項 |
|-|-|-|
| 網羅性（ファイル） | OK / 要修正 | |
| 網羅性（テスト） | OK / 要修正 | |
| ③との整合性 | OK / 要修正 | |
| 規約遵守 | OK / 要修正 | |
| 未確定事項の明記 | OK / 要修正 | |

### 総合判定
OK（③コード生成へ進行可） / 要修正（下記を計画書に反映してから再チェック）
```

「要修正」がある場合は、実行計画書の該当箇所も合わせて修正してください（修正内容がわかるよう、何をどう直したかを応答内で説明する）。

## 目視確認（人間によるチェック）

AIによる自動チェックが完了しても、**ここで作業を止めてください**。次の `/impl:code`（③コード生成、実際にサブエージェントへ実装を委譲する工程）へは自動で進まないこと。

チェック結果を提示したうえで、以下をユーザーに確認してください。

- 実行計画書の内容（作成ファイル一覧・実装要点・未確定事項）が意図通りか
- 未確定事項がある場合、その方針でよいか
- 次の `/impl:code` に進んでよいか

ユーザーの明示的な承認を得るまで、③コード生成は開始しないでください。
