# 実装コード セルフチェック（AI + 目視）

これは実装フローの④番目の手順です。③で生成されたコードを、⑤カバレッジ計測に進む前に検証します。

## 入力

`$ARGUMENTS` を解釈してください。想定される内容:

- 1つ目: 実装先プロジェクトのルートパス（③でコードを生成した場所）
- 2つ目: 「〇〇機能_Go実装仕様書」（③）のパス
- 3つ目: 規約ドキュメントディレクトリのパス
- 4つ目（省略可）: 実行計画書のパス

## 作業内容（AIによる自動チェック）

1. **仕様適合性**: ③「2. ディレクトリ構成」の全ファイルが実際に作成されているか。struct/interface定義・メソッドシグネチャが③の記載と一致しているか
2. **規約遵守**: 生成コードが規約（アーキテクチャ／コーディング／Gorm／Gin）に反していないか
3. **ビルド・静的解析**: 対象言語のビルド（例: `go build ./...`）・静的解析（例: `go vet ./...`、lintがあれば実行）がエラーなく通るか
4. **未実装の検出**: スタブ・TODO・パニックのみのダミー実装・空関数が残っていないか（コード内を検索して確認する）
5. **テスト実行**: 対応するテストコードが存在し、実行して全てパスするか
6. **③からの補足事項**: ③に記載のない詳細を補った箇所があれば、その旨がコード内コメントまたは実装報告に明記されているか

## 出力

チェック結果をチャット上に以下の形式で提示してください（ファイルへの保存は必須としない。ただし実行計画書が渡されている場合はその末尾に追記してもよい）。

```markdown
## 実装セルフチェック結果（AI・実施日: {日付}）

| 観点 | 結果 | 指摘事項 |
|-|-|-|
| 仕様適合性（③との一致） | OK / 要修正 | |
| 規約遵守 | OK / 要修正 | |
| ビルド・静的解析 | OK / 要修正 | |
| 未実装の有無 | OK / 要修正 | |
| テスト実行結果 | OK / 要修正 | |

### 総合判定
OK（⑤カバレッジ計測へ進行可） / 要修正
```

「要修正」がある場合、指摘事項を具体的に列挙してください。この場で自動修正はせず（修正が必要な場合は `/impl:code` に戻ってサブエージェントへ差し戻す）、指摘内容をユーザーに提示してください。

## 目視確認（人間によるチェック）

AIによる自動チェックが完了しても、**ここで作業を止めてください**。次の `/impl:coverage`（⑤カバレッジ計測）へは自動で進まないこと。

チェック結果を提示したうえで、以下をユーザーに確認してください。

- 生成されたコードの内容（主要ファイルの実装方針）が意図通りか
- 「要修正」の指摘があれば、`/impl:code` に戻って修正するか、この場で許容するか
- 次の `/impl:coverage` に進んでよいか

ユーザーの明示的な承認を得るまで、⑤カバレッジ計測は開始しないでください。
