# ①Rails現行仕様書 作成

設計3段（①Rails現行仕様書 → ②Go移行・設計仕様書 → ③Go実装仕様書）の①番目の手順です。

## 最初に必ず読むファイル

**他の作業の前に、以下を読み込んでください。読まずに書き始めてはいけません。**

- `計画書/Rails現行仕様書/Rails現行仕様書_作成プロンプト.md`

このプロンプトが、調査対象（Controller / Service / Form Object / Model / Query / Serializer / Job・Mailer / Migration・Schema / Test）・機能分類ルール・出力フォーマット（全10節）・禁止事項・判断基準をすべて規定しています。以降の作業は、このプロンプトの指示に従ってください。本コマンドの記載とプロンプトが矛盾する場合は、プロンプトを優先します。

## 入力

`$ARGUMENTS` を解釈してください。想定される内容:

- 1つ目: 対象の機能名（例: `認証機能`・`タスク管理機能`）。`Rails現行機能一覧.md` 自体を作る場合は「機能一覧」と指定される
- 2つ目（省略可）: Railsプロジェクトのルートパス。省略時は `/Users/yuta20253/Desktop/edu-platform/rails`
- 3つ目（省略可）: 出力先ディレクトリ。省略時は `/Users/yuta20253/Desktop/edu-platform/rails/tmp/Rails現行仕様書`

パスが曖昧・不足している場合は、推測せずユーザーに確認してください。

## 作業内容

1. 作成プロンプトを読み込む
2. 出力先ディレクトリに同名ファイルが既にある場合、上書き前にユーザーに確認する
3. Railsコードベースを解析し、プロンプト「調査対象」の各項目を確認する
4. プロンプト「機能分類ルール」に従い、Controller / Service 単位ではなく業務機能単位で整理する
5. プロンプト「機能仕様書フォーマット」の全10節で出力する

## Railsリポジトリの扱い

Railsリポジトリは**読み取りのみ**です。ファイルの変更・ブランチ切り替え・コミットを行わないでください。解析を始める前に、Rails側が `main` であることを確認してください（`git -C <Railsのパス> branch --show-current`）。`main` でない場合は、そのまま進めずユーザーに伝えてください。

## 出力

- 機能ごと: `〇〇機能_Rails現行仕様書.md`
- 全体: `Rails現行機能一覧.md`

## 禁止事項

- 作成プロンプトを読まずに書き始める
- Railsコードの説明書にする（業務機能単位で、システムの振る舞いを書く）
- 不明な仕様を推測で埋める（「確認できない事項」として記載する）
- 変更履歴を示す表現（「追記」「更新」「差分」「新規追加」等）を文書に書く
- Railsリポジトリを変更する

## 完了時

作成した文書と、プロンプト「調査対象」の各項目をどう確認したかを提示してください。次は `/spec:design` で②Go移行・設計仕様書に進む旨を伝えてください。
