# Goソースコード 自動生成プロンプト

## 目的

添付された「〇〇機能_Go実装仕様書」（③）をもとに、
実際に動作するGoソースコード一式を実装してください。

この資料の目的は、

> 「③で定めた実装仕様を、そのままコードとして具現化する」

ことです。

③で決定した設計判断（package構成・struct/interface定義・メソッドシグネチャ・クエリ内容・Validation/Authorization/Error方針・テストケース）の再検討は目的ではありません。

---

# 基本方針（運用ルール）

以下を厳守してください。

- **実装作業はメインエージェントが直接書かず、Agentツール（サブエージェント）に委譲すること。** これは今後の恒久的な運用ルールであり、本プロンプトに限らずソースコード作成全般に適用する
- **1機能（Bounded Context）につきサブエージェント1体**を起動し、③の「2. ディレクトリ構成」に記載された全ファイル（domain/application/infrastructure/presentationの該当レイヤー、Active Record/Transaction Script採用時はその構造）を、そのサブエージェントに一括で実装させる。レイヤー単位で複数サブエージェントに分割しない
- テストコード（③「16. テストケース設計」に対応するDomain Test/UseCase Test/Repository Test/Handler Test/Integration Test等、採用パターンに応じた読み替え後の区分）も同一サブエージェントの実装対象に含める
- ③・②で決定した内容を変更しない。矛盾する実装をしない
- `規約/`ディレクトリ配下（アーキテクチャ規約.md・コーディング規約.md・Gorm規約.md・Gin規約.md）を厳守する
- ③に記載のない実装詳細を補う必要がある場合は、「③からの補足」であることを明示する
- スタブ・TODO・未実装のまま完了報告しない。関数本体のロジックを完全に実装する

---

# メインエージェント（オーケストレーター）の作業手順

## 1. 事前分析

サブエージェントを起動する前に、以下を確認してください。

- 対象の`〇〇機能_Go実装仕様書`（③）
- `規約/アーキテクチャ規約.md`・`規約/コーディング規約.md`・`規約/Gorm規約.md`・`規約/Gin規約.md`
- ③「2. ディレクトリ構成」に記載された、作成対象のファイル一覧
- ③「1. 機能概要」から、採用設計パターン（Transaction Script / Active Record / Domain Model / Event Sourcing）

## 2. サブエージェント用プロンプトの作成

Agentツールで起動するサブエージェントには、以下を過不足なく含む自己完結型のプロンプトを渡してください（サブエージェントは会話の前提を共有していないため）。

- 何を実装するか（対象機能名・Bounded Context名・採用設計パターン）
- ③実装仕様書の該当ファイルパス、および規約4点のファイルパス（サブエージェント自身に読ませる）
- ③「2. ディレクトリ構成」に記載の作成対象ファイル一覧（パス単位）
- 実装対象のリポジトリ／配置先ディレクトリ（`internal/`のルートパス等、本ドキュメント自体ではなく実際のGoプロジェクトの場所）
- 遵守事項：③・②の設計判断を変更しない、規約に反しない、③に記載のない業務ルールを新設しない、スタブを残さない
- テストコードも実装対象に含める旨
- 完了時に行うべきこと：`go build ./...`・`go vet ./...`・対象パッケージの`go test`を実行し、結果を報告する

## 3. サブエージェントの実行と検証

- Agentツールでサブエージェントを起動する（`isolation: "worktree"`は、既存コードへの影響を確認してから統合したい場合に使用を検討する）
- 完了後、メインエージェントは以下を確認する
  - 生成されたコードが③の「2. ディレクトリ構成」の全ファイルをカバーしているか
  - struct/interface定義・メソッドシグネチャが③の記載と一致しているか
  - 規約（アーキテクチャ／コーディング／Gorm／Gin）に反する記述がないか
  - `go build`・`go vet`・テストが通っているか（サブエージェントの報告を鵜呑みにせず、必要であれば自身でも実行し確認する）
- 差分やビルド結果に問題がある場合、具体的な指摘内容を明記して同じサブエージェント（SendMessageで継続）に修正を依頼する。メインエージェントが直接修正コードを書かない

---

# 禁止事項

以下は禁止してください。

- メインエージェントが実装コードを直接記述する（サブエージェントへの委譲を経ない）
- ③・②で決定した設計方針（設計パターン・Bounded Context・Aggregate・Repository/UseCase構成等）を変更する
- `規約/`ディレクトリ配下の規約に反する実装をする
- ③に根拠のない業務ルール・実装詳細を無断で追加する
- スタブ・TODOコメント・未実装のまま完了とする
- ③「16. テストケース設計」に記載のあるテストケースを省略する
- ビルド・テストの実行結果を確認せずに完了報告する

---

# 完成条件

以下を満たした状態を完成とします。

- ③「2. ディレクトリ構成」に記載された全ファイルが実装されている
- 各struct／interfaceのフィールド・メソッドシグネチャが③の記載と一致している
- `go build ./...`・`go vet ./...`がエラーなく通る
- ③「16. テストケース設計」に対応するテストコードが存在し、パスする
- 規約（アーキテクチャ／コーディング／Gorm／Gin）に反する記述がない
- ③に記載のない詳細を補った場合、その旨と判断理由が報告されている
