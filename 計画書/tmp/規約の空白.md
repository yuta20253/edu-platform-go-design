# 規約自体に残る「空白」(2026-11-18時点)

`計画書/規約/`(アーキテクチャ・コーディング・Gorm・Gin)に定めがなく、気づいた機能側で個別に判断して乗り切っている論点。個々の②③の誤りではないが、今後追随・新規作成する機能で同じ判断が重複・食い違う恐れがある。

| 論点 | 現状の扱い |
|-|-|
| 定期実行(`scheduler`)共通基盤の置き場所 | 管理者お知らせ管理機能③がスコープ外と明記し持ち越し |
| ページネーションMeta DTOの置き場所 | 各Context個別か`internal/shared/`かが未定 |
| Value Objectの永続化方式(`Scanner`/`driver.Valuer`) | 目標管理・タスク管理が個別に採用 |
| 削除操作を持たないContextでの`gorm.DeletedAt`扱い | タスク下書きが`*time.Time`を選択、規約へ未反映 |
| 生成列(GENERATED COLUMN)の扱い | 面談機能がモデルに定義しないことで回避 |
| `errors`配列の複数メッセージ対応 | アーキ規約(複数可)とGin規約(1件のみ)が食い違う |
| 404エラー本文の形の例外規定 | 目標管理・タスク管理が個別分岐、規約化は未判断(`Go移行_残タスクまとめ.md`1-1の追従後に再検討が必要) |
| 内部専用Context(HTTPエンドポイントなし)の③節構成 | ユーザー基盤③が7節に独自縮小、自動生成プロンプトに例外規定なし |

対応: いずれも「規約に書くべきだと判断したらユーザーに確認する」(CLAUDE.md)に従い、規約化するか個別対応のままにするかを決める。
