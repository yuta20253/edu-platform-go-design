# お知らせ機能 Rails現行仕様書

---

# 1. 機能概要

- 機能の目的
  - 生徒が、自分に配信されたお知らせを一覧・詳細で読めるようにすること。
- システム上の役割
  - **参照専用の機能である。** 生徒がお知らせを作成・更新・削除することはできない。
  - お知らせ自体は、教員（教師お知らせ機能）・管理者（管理者お知らせ管理機能）・システム（承認・却下等の自動通知）が作成する。本機能はそれを読む側だけを担う。
  - 「自分に配信されたか」の判定は、お知らせに紐づく**配信先の指定**（全員・権限別・学年別・学校別・ユーザー個別の5種類）と、生徒の所属（学校・学年・権限）・識別子を突き合わせて行う。
  - 配信済みのお知らせのみを対象とする。下書き・予約状態のものは生徒から見えない。
- 利用者
  - `student` ロールのユーザー（生徒）

---

# 2. 機能一覧

|操作|概要|
|-|-|
|お知らせ一覧取得|自分に配信された配信済みのお知らせを、配信日時の新しい順にページ単位で取得する|
|お知らせ詳細取得|自分に配信された配信済みのお知らせ1件を取得する|

---

# 3. 業務フロー

1. 生徒がお知らせ一覧を要求する。必要に応じてページを指定する。
2. システムは、お知らせの配信先の指定と生徒の所属・識別子を突き合わせ、生徒に配信されたお知らせを絞り込む。
3. そのうち配信済みのものだけを、配信日時の新しい順に並べてページ単位で返す。
4. 生徒が一覧からお知らせを選び、詳細を要求する。
5. システムは同じ絞り込みで対象を取得する。該当しない場合はエラーとして返す。
6. お知らせの本文と発行者を返す。

# 5. API / 処理詳細

## `Api::V1::Student::AnnouncementsController#index`

### 概要

自分に配信された配信済みのお知らせを、配信日時の新しい順にページ単位で返す。

### Request

|項目|必須|型|説明|
|-|-|-|-|
|`page`|任意|integer|ページ番号。0以下・数値以外は未指定として扱う|
|`per_page`|任意|integer|1ページあたりの件数。**既定5**、上限100。0以下・数値以外は既定値|

### 処理内容

1. 操作者に配信されたお知らせを、配信先の指定との突き合わせで絞り込む。
2. そのうち状態が配信済みのものに限る。
3. 配信日時の降順、同値なら識別子の降順に並べる。
4. 指定されたページを取得し、発行者の情報とあわせて返す。

### 業務ルール

#### 配信先の突き合わせ

お知らせには1件以上の配信先が紐づく。配信先は5種類あり、種類ごとに突き合わせの条件が異なる。いずれか1つでも条件を満たせば、そのお知らせは操作者に配信されたものとして扱う。

|配信先の種類|突き合わせの条件|
|-|-|
|全員（`all_users`）|配信先の高校が未設定、または操作者の所属校と一致する|
|権限別（`by_role`）|配信先の権限が操作者の権限と一致し、かつ配信先の高校が未設定または操作者の所属校と一致する|
|学年別（`by_grade`）|配信先の学年が操作者の学年と一致し、かつ配信先の権限が未設定または操作者の権限と一致する|
|学校別（`by_school`）|配信先の高校が操作者の所属校と一致する|
|ユーザー個別（`by_user`）|配信先のユーザーが操作者と一致する|

複数の配信先が同時に条件を満たしても、お知らせは1件として返る（重複しない）。

#### 絞り込みと並び順

- **状態が配信済みのお知らせのみを返す。** 下書き・予約状態のものは含まない。
- 並び順は配信日時の降順。同じ配信日時のものは識別子の降順とする。
- ページネーションの**1ページあたりの既定値は5件**である。他のAPIの既定値（20件）と異なる。上限は全APIで共通の100件。
- 該当するお知らせがない場合は空の配列とページ情報を返す。エラーにしない。
- システムが自動生成したお知らせ（承認・却下等の通知）も、配信先が一致すれば対象に含まれる。本機能で区別しない。

### Database変更

- なし

### Response

HTTP Status は `200`。

|項目|型|説明|
|-|-|-|
|`announcements`|array|お知らせの配列|
|`announcements[].id`|integer|お知らせの識別子|
|`announcements[].title`|string|件名|
|`announcements[].content`|string|本文|
|`announcements[].published_at`|datetime|配信日時|
|`announcements[].publisher`|object|発行者|
|`announcements[].publisher.id`|integer|発行者の識別子|
|`announcements[].publisher.name`|string|発行者の氏名|
|`announcements[].publisher.name_kana`|string|発行者の氏名カナ|
|`meta.current_page`|integer|現在のページ番号|
|`meta.total_pages`|integer|総ページ数|
|`meta.total_count`|integer|総件数|
|`meta.per_page`|integer|1ページあたりの件数|

状態（`status`）・予約日時（`scheduled_at`）・配信先（`announcement_targets`）・システム生成かどうか（`system_generated`）は返さない。**一覧でも本文（`content`）を返す。**

### Errorケース

|条件|HTTP Status|内容|
|-|-|-|
|該当なし|200|空の配列とページ情報を返す。エラーにしない|
|未認証|401|認証されていない|
|`student` ロール以外|403|`{"errors": ["この操作を行う権限がありません"]}`|

## `Api::V1::Student::AnnouncementsController#show`

### 概要

自分に配信された配信済みのお知らせ1件を返す。

### Request

|項目|必須|型|説明|
|-|-|-|-|
|`id`|必須|integer|お知らせの識別子。パスに含まれる|

### 処理内容

1. 操作者に配信されたお知らせを、配信先の指定との突き合わせで絞り込む。
2. そのうち状態が配信済みのものに限る。
3. 指定された識別子のお知らせを取得する。該当しない場合はエラーを返す。
4. お知らせと発行者の情報を返す。

### 業務ルール

- 配信先の突き合わせと配信済みの絞り込みは一覧取得と同じ。
- **自分に配信されていないお知らせ、および配信済みでないお知らせは `404` となる。** 存在しないお知らせと同じ扱いであり、存在するが見る権限がないことを区別しない。
- `404` の本文に入るモデル名が英語表記（`Announcement`）になるのは、日本語訳が定義されていないためである。`announcements.scheduled_at` には「配信日時」という訳があるが、モデル名の訳はない。

### Database変更

- なし

### Response

HTTP Status は `200`。最上位はJSONオブジェクト。項目は一覧の各要素と同じ（`id`・`title`・`content`・`published_at`・`publisher`）。`announcements` のようなキーでは包まない。

### Errorケース

|条件|HTTP Status|内容|
|-|-|-|
|自分に配信されていない、配信済みでない、存在しない|404|`{"message": "Announcementが見つかりません"}`|
|未認証|401|認証されていない|
|`student` ロール以外|403|`{"errors": ["この操作を行う権限がありません"]}`|

# 6. データモデル

|テーブル|役割|主なカラム|
|-|-|-|
|`announcements`|お知らせ本体|`id`, `title`, `content`, `status`, `published_at`, `scheduled_at`, `publisher_id`, `system_generated`|
|`announcement_targets`|お知らせの配信先|`id`, `announcement_id`, `target_type`, `user_role_id`, `grade_id`, `high_school_id`, `user_id`|
|`users`|ユーザー（発行者・配信先・操作者）|`id`, `name`, `name_kana`, `user_role_id`, `grade_id`, `high_school_id`|
|`user_roles`|ロール|`id`, `name`|
|`grades`|学年|`id`, `high_school_id`, `year`|
|`high_schools`|高校|`id`, `name`|

リレーション:

- `announcements` は1人の発行者（`users`）に属する。`publisher_id` は未設定を許さない。
- `announcements` は複数の `announcement_targets` を持つ。お知らせを削除すると配信先も削除される。
- `announcement_targets` の `user_role_id`・`grade_id`・`high_school_id`・`user_id` はいずれも**未設定を許す。** 配信先の種類によって、どの列を使うかが変わる。

`announcements.status`（整数で保持）:

|値|状態|意味|
|-|-|-|
|0|`draft`|下書き。配信されていない|
|1|`scheduled`|予約。予約日時に配信される|
|2|`published`|配信済み|

既定値は `0`（下書き）。

`announcement_targets.target_type`（整数で保持）:

|値|種類|使う列|
|-|-|-|
|0|`all_users`|`high_school_id`（任意）|
|1|`by_role`|`user_role_id`、`high_school_id`（任意）|
|2|`by_grade`|`grade_id`、`user_role_id`（任意）|
|3|`by_school`|`high_school_id`|
|4|`by_user`|`user_id`|

既定値は `0`（全員）。

`system_generated` は、システムが自動生成したお知らせ（承認・却下・申請発生等の通知）を示す。既定値は `false`。本機能の絞り込み・レスポンスでは使わない。

論理削除の扱い:

- `announcements`・`announcement_targets` はいずれも論理削除の列を持たない。削除は物理削除である。
- 発行者（`users`）は論理削除の列を持つが、本機能の絞り込みでは使わない。**論理削除済みのユーザーが発行したお知らせも、配信先が一致すれば返る。**

本機能が参照するテーブルはいずれも本機能が所有するものではない。`announcements`・`announcement_targets` は教員・管理者が作成し、`users`・`grades`・`high_schools` は他機能が管理する。

# 7. 状態管理

お知らせは3つの状態を持つ。本機能は状態を変更しない。

```
draft（下書き）
  ├─→ scheduled（予約）
  └─→ published（配信済み）

scheduled（予約）
  └─→ published（配信済み）

published（配信済み）
  └─→ （遷移先なし）
```

状態変更の条件:

- 下書き → 予約・配信済み、予約 → 配信済みのみ許される。これ以外の組み合わせは拒否される。
- 配信済みからは遷移できない。また配信済みのお知らせは編集・削除もできない。
- 状態が配信済みに変わるとき、配信日時（`published_at`）が未設定であれば現在時刻が設定される。既に設定されている場合は上書きしない。

**本機能から見える状態は配信済みのみである。** 下書き・予約のお知らせは絞り込みで除外される。状態を変える操作は教師お知らせ機能・管理者お知らせ管理機能、および予約配信の自動切替が担う（管理者お知らせ管理機能①「9. 非同期処理」）。

---

# 8. 権限制御

- 利用可能ユーザー: `student` ロールのユーザーのみ。
- 未認証のアクセスは `401`。`student` 以外のロールは `403`。
- 閲覧制限: **配信先の突き合わせがそのまま閲覧制限になっている。** 自分に配信されていないお知らせは一覧に現れず、詳細も `404` となる。
- 操作制限: 作成・更新・削除の操作を提供しない。ルーティングも一覧・詳細に限られている。
- 発行者の氏名・氏名カナは返すが、メールアドレス等の他の情報は返さない。

---

# 9. 非同期処理

- 本機能に非同期処理はない。参照はすべてリクエスト時に同期で実行される。
- ただし、**予約状態のお知らせを配信済みへ切り替える自動処理が別に存在する**（管理者お知らせ管理機能①「9. 非同期処理」）。この処理によって、本機能の一覧に新たなお知らせが現れることがある。本機能はその契機を持たない。

# 10. Rails実装対応表

|種類|実装|
|-|-|
|Controller|`Api::V1::Student::AnnouncementsController`|
|Model|`Announcement`（`for_user` による配信先の突き合わせ）, `AnnouncementTarget`, `User`|
|Serializer|`AnnouncementSerializer`, `AnnouncementPublisherSerializer`|
|Service / Form / Query / Job|なし|

配信先の突き合わせは `Announcement.for_user(user)` が担う。配信先の種類ごとに条件を分けた5つの検索を1つにまとめ、重複を除いてからお知らせと結合する実装になっている。識別子の集合を条件に入れる形ではなく派生テーブルとして結合しているのは、MySQLで全件評価にならないようにするためである（実装内のコメント）。
