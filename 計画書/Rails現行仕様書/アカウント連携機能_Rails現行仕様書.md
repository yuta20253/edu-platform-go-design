# アカウント連携機能 Rails現行仕様書

---

# 1. 機能概要

- 機能の目的
  - 教員によって事前に招待登録された未利用の生徒アカウント（学籍情報のみが設定された仮アカウント）を、生徒が現在ログインしているアカウントへ統合し、学籍情報（高校・学年・クラス・生徒番号）を引き継ぐこと。
- システム上の役割
  - 生徒が学校から渡された生徒番号を入力すると、対応する招待済み未利用アカウントを検索し、その学籍情報を現在ログイン中のアカウントに統合する。
  - 統合元となった仮アカウントは論理削除され、以後ログインに利用できなくなる。
  - 統合の成功・失敗を問わず、統合の試行内容を監査ログとして記録する。
- 利用者
  - `student` ロールのユーザー（生徒）

---

# 2. 機能一覧

|操作|概要|
|-|-|
|アカウント連携|生徒番号を指定し、招待済み未利用アカウントの学籍情報を現ログインアカウントへ統合する|
|連携プレビュー|統合を確定する前に、対象アカウントの学校・学年・学級名のみを取得する|

---

# 3. 業務フロー

1. 生徒が学校から発行された生徒番号を入力する。
2. 確認画面を表示する場合は、連携プレビューで対象アカウントの学校・学年・学級名を取得して提示する。氏名などの個人情報は返さない。
3. 生徒が内容を確認してアカウント連携を実行する。
4. システムはログイン中アカウントが既に生徒番号を持っていないかを確認し、次に入力された生徒番号の形式を検証する。
5. 生徒番号に一致する、削除されていないアカウントを検索する。
6. 検索したアカウントが以下のいずれかに該当する場合は連携を中止し、失敗として監査ログに記録する。
   - 既に本人が利用開始済み（パスワード再設定が不要な状態）のアカウントである
   - ログイン中アカウントと学校（高校）が異なる
   - 統合対象アカウントに学習履歴などの利用データが既に存在する
7. 上記のいずれにも該当しない場合、対象アカウントの高校・学年・クラス・生徒番号を現ログイン中アカウントへコピーする。
8. 統合元アカウントを論理削除し、生徒番号を除去する（生徒番号の重複を避けるため）。
9. 統合結果（成功）を監査ログに記録する。
10. 結果を返却する。

# 5. API / 処理詳細

## `Api::V1::Student::AccountLinksController#create`

### 概要

生徒が入力した生徒番号をもとに、招待済み未利用アカウントの学籍情報を現ログイン中アカウントへ統合する。

### Request

|項目|必須|型|説明|
|-|-|-|-|
|`student_number`|必須|string|統合対象を特定する生徒番号|

### 処理内容

生徒番号の検証と対象アカウントの検索は`Student::AccountLinkFinder`が担い、`create`と`preview`で共通化されている。

1. ログイン中アカウントが既に生徒番号を持っている場合はエラーとする（既に連携済みの扱い）。形式の検証よりも前に判定する。
2. 入力された生徒番号の形式（英数字1文字以上-英数字1文字以上のハイフン区切り形式）を検証する。形式が不正な場合はエラーとする。
3. 削除されていないアカウントの中から、生徒番号が一致するものを検索する。見つからない場合はエラーとする。
4. 検索したアカウントが以下の条件をすべて満たすか検証する。
   - まだ本人によって利用開始（パスワード再設定）されていないこと
   - ログイン中アカウントと同じ高校に所属していること
   - 学習履歴・目標・タスクなど、業務データが一件も紐づいていないこと
5. 検証をすべて満たした場合、対象アカウントの高校・学年・クラス・生徒番号をログイン中アカウントへ複製する。
6. 対象アカウント（統合元）を論理削除し、生徒番号をクリアする。
7. 監査ログへ統合結果（成功）を記録する。
8. 上記3〜7の過程でエラーが発生した場合、失敗内容をログに記録したうえで、対象アカウントの情報が取得できていれば監査ログにも失敗として記録し、処理全体を取り消す（統合元・統合先いずれのデータも変更されない）。`AccountLinkFinder`は検索済みの対象アカウントを`target_user`として公開しており、検証の途中で例外が発生した場合でも監査ログに統合元のIDを残せるようにしている。

### 業務ルール

- 統合対象にできるのは、教員による招待後、生徒がまだパスワードを設定していない（未利用の）アカウントに限られる。
- 統合対象アカウントは、ログイン中アカウントと同じ高校に所属している必要がある。
- 統合対象アカウントに学習履歴などの利用データが1件でも存在する場合は統合できない。
- 生徒番号は既定の書式（区切り文字を挟んだ英数字の組み合わせ）に従っている必要がある。
- ログイン中アカウントが既に生徒番号を持っている場合は連携できない。
- 生徒番号の存在有無を総当たりで探索されるのを防ぐため、「一致するアカウントが見つからない」と「既に使用されている」をレスポンスで区別しない（同一のメッセージを返す）。
- 連携操作は短時間に繰り返し実行できないよう回数制限が設けられている（同一ユーザーにつき10分間で5回まで）。上限を超えた場合はそれ以上の連携試行を一時的に受け付けない。

### Database変更

作成:

```
account_link_audits
```

更新:

```
users（統合先アカウントの学籍情報、統合元アカウントの論理削除・生徒番号クリア）
```

### Response

- `message`（連携完了メッセージ）

### Errorケース

|条件|HTTP Status|内容|
|-|-|-|
|生徒番号の形式が不正|400|エラーメッセージを返却|
|生徒番号に一致するアカウントが存在しない|404|「見つからないか、すでに使用されています。心当たりがある場合は学校へお問い合わせください」を返却。存在の有無を推測されないよう、既に使用されている場合と同じ文言にしている|
|ログイン中アカウントが既に生徒番号を持っている|400|既に紐付けられている旨のエラー|
|統合対象アカウントが既に利用開始済み|400|既に利用されている旨のエラー|
|統合対象アカウントの学校が異なる|400|生徒コード不一致のエラー|
|統合対象アカウントに利用データが存在する|400|統合できない旨のエラー|
|回数制限を超過|429|一時的に受け付けない旨のレスポンス|
|生徒以外のロールでアクセス|403|権限エラー|
|未認証|401|認証エラー|

## `Api::V1::Student::AccountLinksController#preview`

### 概要

統合を確定する前の確認画面向けに、対象アカウントの所属情報のみを取得する。氏名などの個人情報は返さない。

### Request

|項目|必須|型|説明|
|-|-|-|-|
|`student_number`|必須|string|統合対象を特定する生徒番号|

### 処理内容

1. `Student::AccountLinkPreviewService`が`Student::AccountLinkFinder`を呼び出し、`create`と同一の検証・検索を行う。
2. 対象アカウントの高校名・学年の表示名・学級名を返却する。

### 業務ルール

- 検証・検索の条件は`create`と同一であり、満たさない場合は`create`と同じエラーを返す。
- 返却するのは所属情報（高校名・学年の表示名・学級名）のみとする。氏名・メールアドレスなどは返さない。
- データの変更は行わない。監査ログも記録しない。

### Database変更

- なし

### Response

```json
{
  "high_school_name": "...",
  "grade_display_name": "...",
  "school_class_name": "..."
}
```

いずれの項目も、対象アカウントに該当データが紐づいていない場合は`null`になる。

### Errorケース

`create`と同一。

# 6. データモデル

## `users`

- 役割: 生徒・教員・保護者・管理者などすべてのアカウントを管理するテーブル。アカウント連携機能では、生徒アカウントの学籍情報（高校・学年・クラス・生徒番号）の保持・引き継ぎ元として利用される。
- 主なカラム（本機能に関連するもの）:
  - `id`
  - `high_school_id`
  - `grade_id`
  - `school_class_id`
  - `student_number`（生徒番号。一意）
  - `password_reset_required`（未利用アカウントかどうかを示す）
  - `deleted_at`（論理削除日時）

## `account_link_audits`

- 役割: アカウント連携の試行結果（成功・失敗）を記録する監査ログテーブル。
- 主なカラム:
  - `id`
  - `user_id`（連携を実行したログイン中アカウント）
  - `merged_user_id`（統合元となった仮アカウントのID）
  - `student_number`（統合に使用された生徒番号）
  - `high_school_id`
  - `grade_id`
  - `school_class_id`
  - `result`（`success` / `failed`）
- リレーション:
  - `belongs_to :user`

---

# 7. 状態管理

- 統合元アカウントは、連携が成功すると論理削除（`deleted_at` に日時が設定）され、以後ログインできなくなる。
- `password_reset_required` が `true` のアカウントは「招待済み・未利用」状態を表し、アカウント連携の対象になり得る。連携が成立すると統合元アカウント自体は削除されるため、この状態が引き継がれるわけではない。

---

# 8. 権限制御

- `student` ロールのユーザーのみ利用できる。
- 連携の対象にできるのは、ログイン中アカウントと同じ高校に所属する未利用アカウントに限られる。
- 連携操作にはレート制限が課されており、短時間の連続実行はブロックされる。

---

# 9. 非同期処理

- `AccountLinksController` の処理に紐づく Job / Mailer は見当たらない。
