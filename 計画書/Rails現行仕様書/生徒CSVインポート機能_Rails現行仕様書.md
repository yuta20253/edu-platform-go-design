# 生徒CSVインポート機能 Rails現行仕様書

---

# 1. 機能概要

- 機能の目的
  - 教師がCSVファイルを使って、同校の生徒アカウントをまとめて登録・更新できるようにすること。
- システム上の役割
  - アップロードされたCSVを実際にインポートする前に、内容を検証して結果（正常行数・エラー行数・エラー内容）をプレビューする「事前検証（dry run）」を提供する。
  - CSVの内容を非同期でインポートし、生徒アカウントの新規作成・既存アカウントの更新を行う。
  - インポートの実行履歴（誰が、いつ、どのファイルを、どのような結果でインポートしたか）を記録する。あわせて、インポートが成功した場合は、インポートされた生徒（新規作成か既存生徒の更新か）を履歴ごとに記録する。この記録は、教師が実行結果を確認し、生徒コードを配布するために利用される（「教師インポート履歴管理機能」を参照）。
- 利用者
  - `teacher` ロールのユーザー（教師）

---

|操作|概要|

# 3. 業務フロー

## 事前検証（dry run）

1. 教師がCSVファイルを選択してアップロードする。
2. システムはファイル形式（CSV形式であること、5MB以内であること）を検証する。
3. CSVの各行を1行ずつ検証する（氏名・氏名カナ・メールアドレス・学年・学級の妥当性、学年名・学級名が自校に実在するか、メールアドレスの重複や既存利用状況など）。
4. データベースへの登録・更新は行わず、全体の行数・有効行数・エラーがあった行の内容を返却する。

## インポート実行

1. 教師がCSVファイルを選択してアップロードする。
2. システムはファイル形式を検証する。
3. インポート履歴（処理中状態）を作成し、アップロードされたファイルを添付する。
4. インポートを実行する非同期ジョブを起動し、教師には「インポートを開始しました」という受付完了の応答を即座に返す。
5. 非同期ジョブが起動すると、CSVを1行ずつ検証しながらインポートする。
   - ヘッダーが不正な場合は、その時点でインポート全体を失敗として扱う。
   - 行の内容が不正な場合は、その行をエラーとして記録する。
   - 1行でもエラーがあった場合、インポート全体を失敗とし、生徒データへの反映は一切行わない（全件成功または全件失敗）。
   - 全行が有効な場合、各行について、メールアドレスが同校の既存生徒と一致すれば情報を更新し、一致しなければ新しい生徒アカウントを作成する。あわせて、各行の生徒を「新規作成」または「更新」としてインポート履歴に記録する。
6. インポート結果（成功件数・失敗件数・エラー内容）をインポート履歴に記録する。

# 5. API / 処理詳細

## `Api::V1::Teacher::ImportStudentsController#create`

### 概要

生徒CSVファイルを受け付け、インポート履歴を作成したうえで、非同期でインポートを実行する。

### Request

|項目|必須|型|説明|
|-|-|-|-|
|`file`|必須|file|CSVファイル（`text/csv`、拡張子`.csv`、5MB以内）|
|`mode`|任意|string|インポートモード（`append` または `overwrite`。未指定・不正値の場合は `append`）|

### 処理内容

1. アップロードされたファイルが存在すること、CSV形式（Content-Typeと拡張子）であること、5MB以内であることを検証する。
2. 検証に成功すると、実行した教師に紐づくインポート履歴を「種別：生徒」「状態：処理中」として作成し、CSVファイルを添付する。
3. インポートを実行する非同期ジョブを起動する。
4. `202 Accepted` で「インポートを開始しました」という受付完了の応答を返す（この時点では実際のインポートは完了していない）。
5. （非同期ジョブ内）インポート履歴を「開始日時」付きで処理中状態に更新する。
6. （非同期ジョブ内）CSVのヘッダーが、想定される列（氏名・氏名カナ・メール・学年・学級）をすべて含んでいるか検証する。不足があれば、その時点でインポート全体を失敗とする。
7. （非同期ジョブ内）CSVを1行ずつ検証する。氏名・氏名カナ・メールアドレスの妥当性、学年名・学級名が自校に実在すること、メールアドレスが他校のアカウントや生徒以外のロールで使用されていないこと、CSV内でのメールアドレス重複がないことを確認する。
8. （非同期ジョブ内）1行でも不正な行があれば、その時点で処理全体を失敗として扱い、生徒データへの登録・更新は一切行わない。不正だった行の内容はエラーとしてインポート履歴に記録される。
9. （非同期ジョブ内）全行が有効な場合、各行について、メールアドレスが同校の既存生徒と一致すればその生徒の氏名・氏名カナ・メールアドレス・学年・学級を更新し、一致しなければ新規に生徒アカウントを作成する。あわせて、その行の生徒を、新規作成（`created`）または更新（`updated`）の区別とともにインポート履歴へ成功行として記録する。
10. （非同期ジョブ内）インポート履歴を「完了」または「失敗」の状態に更新し、成功件数・総件数（失敗時はエラー件数）を記録する。

### 業務ルール

- アップロードできるのはCSV形式（`text/csv`、拡張子`.csv`）のファイルのみで、サイズは5MB以内でなければならない。
- CSVの列は「氏名」「氏名カナ」「メール」「学年」「学級」の5列がすべて必須。
- 「学年」「学級」はCSV上では表示名（学年の呼称、学級名）で指定し、自校に実在する学年・学級名でなければならない。学級は指定した学年に属していなければならない。
- メールアドレスは、他校のアカウントで使用されていたり、生徒以外のロール（教員等）のアカウントで使用されていたりする場合はエラーとなる。
- 同一CSV内で同じメールアドレスが複数行に使われている場合はエラーとなる。
- メールアドレスが同校の既存の生徒と一致する行は、新規作成ではなく既存生徒情報の更新として扱われる（氏名・氏名カナ・メールアドレス・学年・学級を上書きする。パスワードや認証状態などは変更されない）。
- 1件でも不正な行が含まれる場合、CSV全体のインポートが失敗し、有効な行についても生徒データへの反映は行われない（部分的な取り込みは行わない）。この場合、成功行の記録も残らない（生徒の作成・更新と成功行の記録は、同一の処理として全件成功または全件失敗になる）。
- 成功行の記録は、1つの履歴につき1人の生徒を1回だけ記録する。CSV内で同じメールアドレスが重複している場合はエラーとなるため、同じ生徒が同じ履歴に重複して記録されることはない。
- リクエストで `high_school_id` 等、所属校を指定するパラメータを送っても無視され、常に実行した教師の所属高校としてインポートされる。
- `mode` パラメータは受け付けるが、生徒CSVインポートの現在の実装では `overwrite` 指定時に既存データを事前削除するような処理は行われない（メールアドレス一致による更新／新規作成のみで判定される）。

### Database変更

作成:

```
import_histories（インポート履歴。状態は処理中→完了または失敗と変化する）
```

非同期ジョブ実行後、全行が有効な場合に作成・更新:

```
users（新規生徒アカウントの作成、または既存生徒アカウントの更新）
imported_students（インポートされた生徒の記録。新規作成か更新かを区別する）
```

非同期ジョブ実行後、不正な行があった場合に作成:

```
import_errors（不正だった行番号とエラー内容）
```

### Response

- `message`: `インポートを開始しました`

### Errorケース

|条件|HTTP Status|内容|
|-|-|-|
|ファイルが存在しない、CSV形式でない、5MBを超える|422|`errors` を返却（インポート履歴は作成されない）|
|CSVのヘッダーが不正（非同期ジョブ実行後に判明）|202（受付時点）。ジョブ実行後、インポート履歴が失敗状態になる|`errors`／履歴上のエラーメッセージとして`CSVのフォーマットが不正です`|
|行内容が不正（非同期ジョブ実行後に判明）|202（受付時点）。ジョブ実行後、インポート履歴が失敗状態になる|履歴上のエラーメッセージとして各行の検証エラー内容|
|未認証|401|-|
|教師以外（生徒・保護者・管理者等）のアクセス|403|-|

## `Api::V1::Teacher::ImportStudentsController#dry_run`

### 概要

CSVファイルの内容を検証し、実際のデータ登録・更新を行わずに検証結果を返す。

### Request

|項目|必須|型|説明|
|-|-|-|-|
|`file`|必須|file|CSVファイル（`text/csv`、拡張子`.csv`、5MB以内）|

### 処理内容

1. アップロードされたファイルの形式・サイズを検証する。
2. CSVのヘッダーが想定される列をすべて含んでいるか検証する。不足があればエラーとする。
3. CSVを1行ずつ検証する（`create`と同様の検証内容）。
4. インポート履歴の作成や生徒データへの反映は一切行わず、全体の行数・有効行数・エラーがあった行（行番号・エラー内容・行データ）を返却する。エラー行の詳細は最大100件まで返却する（超過分は集計のみに反映される）。

### 業務ルール

- 検証内容は`create`アクションの非同期ジョブ内で行われる検証と同一だが、結果はレスポンスとして即座に返却され、データベースへの書き込みは一切発生しない。
- エラー内容の詳細表示は最大100行まで。全体の件数集計（総件数・有効件数）は上限に関わらず正しく計算される。

### Database変更

- なし

### Response

- `total_count`: CSVの総行数
- `valid_count`: 検証に成功した行数
- `rows`: エラーがあった行の一覧（`row_number`：行番号, `severity`：`error`, `message`：エラー内容, `data`：行の内容）

### Errorケース

|条件|HTTP Status|内容|
|-|-|-|
|ファイルが存在しない、CSV形式でない、5MBを超える|422|`errors` を返却|
|CSVのヘッダーが不正|422|`errors` を返却|
|未認証|401|-|
|教師以外のアクセス|403|-|

# 6. データモデル

## `import_histories`

- 役割: CSVインポートの実行履歴（種別・状態・件数・実行者・添付ファイル）を記録するテーブル
- 主なカラム: `id`, `user_id`（実行した教師）, `unit_id`（生徒インポートでは使用しない）, `file_name`, `file_size`, `content_type`, `status`, `total_count`, `success_count`, `error_count`, `started_at`, `finished_at`, `deleted_at`, `mode`, `import_type`
- リレーション: `belongs_to :user`, `belongs_to :unit`（任意）, `has_many :import_errors`, `has_many :imported_students`, `has_one_attached :file`（アップロードされたCSVファイル本体）
- `import_type` は `question`（問題インポート）と `student`（生徒インポート）を区別する区分。本機能では `student` が使用される。
- `mode` は `append`（追加）・`overwrite`（上書き）の区分。生徒インポートでは値として保持されるが、現状の処理は行ごとのメールアドレス一致判定のみで、事前の一括削除等は行われない。

## `import_errors`

- 役割: インポート実行時にエラーとなった行の内容を記録するテーブル
- 主なカラム: `id`, `import_history_id`, `row_number`（エラーが発生したCSV上の行番号）, `message`（エラー内容）
- リレーション: `belongs_to :import_history`

## `imported_students`

- 役割: 生徒インポートで成功した行の生徒を、インポート履歴ごとに記録するテーブル。インポート実行時に本機能が書き込み、参照は教師インポート履歴管理機能が行う。
- 主なカラム: `id`, `import_history_id`, `user_id`（インポートされた生徒）, `action`（`created`：新規作成、`updated`：既存生徒の更新）
- 制約: 同じ履歴に同じ生徒を重複して記録できない（`import_history_id` と `user_id` の組で一意）
- リレーション: `belongs_to :import_history`, `belongs_to :user`

# 7. 状態管理

```
pending（未処理）
  ↓（ジョブ開始）
processing（処理中）
  ↓                              ↓
completed（完了）           failed（失敗）
```

状態変更条件:

- `create`実行時点でインポート履歴は「処理中」として作成される。
- 非同期ジョブが開始すると、開始日時を記録したうえで改めて「処理中」に更新される。
- CSV全行の検証・登録が問題なく完了すると「完了」になり、成功件数・総件数が記録される。あわせて、インポートされた生徒が成功行として記録されている（生徒の作成・更新と同じ処理で確定する）。
- ヘッダー不正、またはいずれかの行の検証エラーがあった場合は「失敗」になり、エラー件数・総件数が記録され、エラー内容が`import_errors`に保存される。失敗時、生徒データへの登録・更新は行われず、成功行の記録も残らない。

---

# 8. 権限制御

- 生徒CSVインポート（事前検証・インポート実行とも）は `teacher` ロールのユーザーのみ利用できる。生徒・保護者・管理者はアクセスできない。
- インポート対象・作成対象の生徒アカウントは、常に実行した教師の所属高校に限定される。リクエストで所属校を明示的に指定しても無視される。
- 実行したインポートの履歴（結果・インポートされた生徒・エラー明細）と、生徒コード配布用CSVの取得は、教師インポート履歴管理機能で提供される。教師が参照できるのは自身が実行したインポートの履歴のみである。

---

# 9. 非同期処理

- `Teacher::StudentCsvImportJob`：`create`アクションから起動され、インポート履歴IDを受け取ってCSVの検証・生徒データへの反映・履歴更新をまとめて行う。ヘッダー不正時・行エラー時はインポート履歴を失敗状態にし、エラー内容を保存する。全行有効な場合のみ生徒アカウントの作成・更新を行い、履歴を完了状態にする。
- インポートによって新規作成された生徒アカウントには、他の生徒アカウント作成経路（教師による単体登録）と同様に、仮パスワード発行と招待メール送信が行われる。
