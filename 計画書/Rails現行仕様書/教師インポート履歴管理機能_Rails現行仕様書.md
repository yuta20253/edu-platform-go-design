# 教師インポート履歴管理機能 Rails現行仕様書

---

# 1. 機能概要

- 機能の目的
  - 教師が、自身が実行した生徒CSVインポートの結果を確認し、インポートされた生徒に配布する生徒コードの一覧をCSVファイルとして取得できるようにすること。
- システム上の役割
  - 自身が実行した生徒CSVインポートの履歴を、状態・期間で絞り込み、並び替えして一覧表示する。
  - インポート履歴の詳細として、実行結果の件数、インポートされた生徒の一覧（新規作成か更新か）、エラー明細を提供する。
  - インポートされた生徒の氏名・氏名カナ・学年・学級・生徒コードを、生徒へ配布するためのCSVファイルとして出力する。
- 利用者
  - `teacher` ロールのユーザー（教師）

インポート履歴（`import_histories`）は問題インポート・生徒インポートのいずれの実行時にも共通して記録されるデータであるが、本機能が一覧・詳細・CSVエクスポートの対象として扱うのは、ログイン中の教師自身が実行した生徒インポートの履歴のみである。問題インポートは管理者が担当する別機能であり、その履歴は本機能の対象には含まれない。他の教師が実行した生徒インポートの履歴も、同じ学校の教師であっても対象には含まれない。

インポートされた生徒（成功行）の記録は、生徒CSVインポート機能がインポート実行時に残す。本機能はその記録を参照するのみである。

---

# 2. 機能一覧

|操作|概要|
|-|-|
|一覧取得|自身が実行した生徒インポートの履歴を、条件で絞り込んで一覧取得する|
|詳細取得|指定した履歴の詳細（実行結果の件数・インポートされた生徒・エラー明細）を取得する|
|CSVエクスポート|指定した履歴でインポートされた生徒の生徒コード配布用CSVを出力する|

---

# 3. 業務フロー

1. 教師が生徒CSVインポートを実行する（「生徒CSVインポート機能」を参照）。
2. 教師がインポート履歴一覧画面を開く。状態・期間を指定すると、システムは自身が実行した生徒インポートの履歴のうち条件に合致するものを並び替えて一覧取得する。
3. 特定のインポート履歴を選択すると、その履歴の詳細（実行結果の件数、インポートされた生徒の一覧、エラー明細）を取得する。
   - 失敗したインポートでは、エラー明細（エラーとなった行番号と内容）で原因を確認できる。
   - 成功したインポートでは、インポートされた生徒の一覧（新規作成か既存生徒の更新か）を確認できる。
4. 生徒へ生徒コードを配布したい場合は、その履歴でインポートされた生徒の一覧をCSVファイルとしてダウンロードする。

# 5. API / 処理詳細

## `Api::V1::Teacher::ImportHistoriesController#index`

### 概要

ログイン中の教師が実行した生徒インポートの履歴を、条件で絞り込み・並び替えして一覧取得する。

### Request

|項目|必須|型|説明|
|-|-|-|-|
|`status`|任意|string|状態による絞り込み（`pending`、`processing`、`completed`、`failed`）|
|`from`|任意|date|作成日時の期間絞り込み（開始日）|
|`to`|任意|date|作成日時の期間絞り込み（終了日）|
|`sort`|任意|string|並び替え項目（`created_at`、`total_count`、`success_count`、`error_count`、`status` のいずれか。指定外は `created_at` を使用）|
|`order`|任意|string|並び順（`asc` または `desc`。指定外は `desc` を使用）|
|`page`|任意|integer|ページ番号|
|`per_page`|任意|integer|1ページあたり件数（未指定時は20件、最大100件）|

管理者向けの履歴一覧にある単元・コース・実行者による絞り込み（`unit_id`、`course_id`、`user_id`）は、本機能では受け付けない（指定しても無視される）。

### 処理内容

1. 自身が実行した生徒インポートの履歴のうち、論理削除されていないものを対象とする。
2. `status` が有効な値であれば状態で絞り込む。
3. `from`/`to` が指定されていれば、作成日時がその期間に含まれる履歴のみに絞り込む。
4. `sort`/`order` を適用して並び替える（同一条件の場合は ID の降順で並べる）。
5. ページングした結果を返却する。

### 業務ルール

- 対象は自身が実行した生徒インポートの履歴のみである。他の教師が実行した履歴、および問題インポートの履歴は一覧に含まれない。
- 論理削除済みの履歴は一覧に含まれない。
- `status`、`sort`、`order` に許可されていない値が指定された場合は、絞り込み条件を無視するか既定値（`created_at` の降順）で並び替える（エラーにはならない）。
- 期間指定は日付単位で行われ、開始日は当日の 0 時、終了日は当日の 23 時 59 分 59 秒までを含む。日付として解釈できない値は無視される。
- `per_page` は最大 100 件に制限される。
- 検索条件・並び替えの規則は、管理者インポート履歴管理機能の一覧と同一である。

### Database変更

- なし

### Response

- `import_histories`: 各履歴の `id`, `file_name`, `status`, `mode`, `total_count`, `success_count`, `error_count`, `created_at`（生徒・エラー明細は含まない）
- `meta`: `current_page`, `total_pages`, `total_count`, `per_page`

### Errorケース

|条件|HTTP Status|内容|
|-|-|-|
|未認証|401|-|
|教師以外のアクセス|403|-|

## `Api::V1::Teacher::ImportHistoriesController#show`

### 概要

指定された生徒インポート履歴の詳細を、インポートされた生徒の一覧とエラー明細とともに取得する。

### Request

|項目|必須|型|説明|
|-|-|-|-|
|`id`|必須|integer|インポート履歴の ID|

### 処理内容

1. 自身が実行した生徒インポートの履歴（論理削除されていないもの）から、指定された履歴を取得する。
2. 履歴に紐づく、インポートされた生徒（記録された順）と、その学年・学級の情報を取得する。
3. 履歴に紐づくエラー明細（行番号順）を取得する。
4. 履歴情報、生徒の一覧、エラー明細を返却する。

### 業務ルール

- 対象は自身が実行した生徒インポートの履歴のみである。他の教師が実行した履歴、問題インポートの履歴、論理削除済みの履歴の ID を指定した場合は、存在しない履歴として扱われ取得できない。
- 生徒の一覧に表示される氏名・氏名カナ・メールアドレス・学年・学級・生徒コードは、参照した時点の生徒情報であり、インポート実行時点の内容を保存したものではない（インポート後に生徒情報が変更された場合は、変更後の内容が表示される）。
- 学級に所属していない生徒の学級は空（`null`）として返却される。
- 生徒の一覧に含まれるのは、インポートが成功した行の生徒のみである。インポートが失敗した履歴（全件成功・全件失敗のため、生徒データへ反映されていない）や、成功行の記録が存在しない履歴では、生徒の一覧は空になる。
- エラー明細は、エラーとなった行の行番号とメッセージである。

### Database変更

- なし

### Response

- `id`, `file_name`, `status`, `mode`, `total_count`, `success_count`, `error_count`, `started_at`, `finished_at`, `created_at`
- `students`: インポートされた生徒の一覧（`id`, `name`, `name_kana`, `email`, `student_number`（生徒コード）, `grade`（学年の表示名）, `school_class`（学級名。未所属の場合は `null`）, `action`（`created`：新規作成、`updated`：既存生徒の更新））
- `errors`: エラー明細一覧（`row_number`, `message`）

### Errorケース

|条件|HTTP Status|内容|
|-|-|-|
|対象履歴が存在しない、または自身が実行した生徒インポートの履歴でない|404|対象履歴なし|
|未認証|401|-|
|教師以外のアクセス|403|-|

## `Api::V1::Teacher::ImportHistoriesController#export`

### 概要

指定された生徒インポート履歴でインポートされた生徒の一覧を、生徒コード配布用のCSVファイルとして出力する。

### Request

|項目|必須|型|説明|
|-|-|-|-|
|`id`|必須|integer|インポート履歴の ID|

### 処理内容

1. 自身が実行した生徒インポートの履歴（論理削除されていないもの）から、指定された履歴を、インポートされた生徒とその学年・学級の情報とともに取得する。
2. 生徒ごとに、氏名・氏名カナ・学年・学級・生徒コードを1行とするCSVデータを、インポートされた順に生成する。
3. CSVファイルとしてダウンロード返却する。

### 業務ルール

- 対象は自身が実行した生徒インポートの履歴のみである。他の教師が実行した履歴、問題インポートの履歴、論理削除済みの履歴の ID を指定した場合は、存在しない履歴として扱われる。
- CSVの列は「氏名」「氏名カナ」「学年」「学級」「生徒コード」の5列で、メールアドレスは含まれない。学年は学年の表示名、学級は学級名で出力し、学級に所属していない生徒の学級は空欄になる。
- 新規作成された生徒と既存生徒の更新の区別なく、インポートが成功したすべての行の生徒が出力される。
- 氏名・氏名カナ・学年・学級が `=`、`+`、`-`、`@` で始まる場合、表計算ソフトでの誤動作（数式注入）を防ぐため、先頭に `'` を付与してエスケープする。生徒コードはシステムが発行する値であるため、エスケープの対象ではない。
- 文字化けを防ぐため CSV には BOM を付与する。
- 管理者インポート履歴管理機能のCSVと異なり、サマリー行は出力しない（1行目がヘッダー行である）。
- 出力対象の生徒が存在しない履歴（失敗した履歴、成功行の記録が存在しない履歴）では、ヘッダー行のみのCSVが返却される。
- 生徒コードは、生徒が新規登録時に入力して、学校側で事前に作成されたアカウントを有効化するための情報である（「認証機能」を参照）。本機能は、その配布に用いるCSVの出力対象を、自身が実行したインポートの生徒に限定している。

### Database変更

- なし

### Response

- `import_history_<id>.csv` という名称の CSV ファイル（`text/csv; charset=UTF-8`、添付ファイルとしてダウンロード）。1行目はヘッダー行（`氏名`, `氏名カナ`, `学年`, `学級`, `生徒コード`）、以降が生徒の行。

### Errorケース

|条件|HTTP Status|内容|
|-|-|-|
|対象履歴が存在しない、または自身が実行した生徒インポートの履歴でない|404|対象履歴なし|
|未認証|401|-|
|教師以外のアクセス|403|-|

# 6. データモデル

## `import_histories`

- 役割: CSV インポート（問題インポート・生徒インポート）の実行履歴を管理するテーブル
- 主なカラム: `id`, `user_id`（実行した教師）, `unit_id`（生徒インポートでは使用しない）, `file_name`, `file_size`, `content_type`, `status`, `mode`, `import_type`, `total_count`, `success_count`, `error_count`, `started_at`, `finished_at`, `deleted_at`, `created_at`
- リレーション: `belongs_to :user`, `belongs_to :unit`（任意）, `has_many :import_errors`, `has_many :imported_students`, `has_one_attached :file`
- `import_type` により問題インポート・生徒インポートの区別を持つが、本機能が扱うのは生徒インポート（`import_type: student`）の履歴のみである。

## `import_errors`

- 役割: インポート処理で発生した行単位のエラー内容を記録するテーブル
- 主なカラム: `id`, `import_history_id`, `row_number`, `message`
- リレーション: `belongs_to :import_history`

## `imported_students`

- 役割: 生徒インポートで成功した行の生徒を、インポート履歴ごとに記録するテーブル（生徒CSVインポート機能が書き込み、本機能は参照のみ）
- 主なカラム: `id`, `import_history_id`, `user_id`（インポートされた生徒）, `action`（`created`：新規作成、`updated`：既存生徒の更新）
- 制約: 同じ履歴に同じ生徒を重複して記録できない（`import_history_id` と `user_id` の組で一意）
- リレーション: `belongs_to :import_history`, `belongs_to :user`
- 記録の順序: 記録された順（CSVの行順）で参照される。

## `users`（参照）

- 生徒の氏名・氏名カナ・メールアドレス・生徒コード（`student_number`）・学年・学級は、`users` およびその学年・学級の情報を参照して返却する。

# 7. 状態管理

インポート履歴は以下の状態を持つ。

```
pending（実行待ち）
↓
processing（実行中）
↓
completed（完了） または failed（失敗）
```

状態変更条件:

- インポート処理の開始・進行・完了・失敗は、インポート実行機能（生徒CSVインポート機能）側の非同期処理によって更新される。
- 本機能（教師インポート履歴管理機能）は履歴の状態を参照するのみであり、状態を変更する操作は提供しない。
- 生徒インポートは全件成功または全件失敗のいずれかで終了するため、インポートされた生徒（成功行）の記録は、`completed` で終了した履歴にのみ残る。

---

# 8. 権限制御

- `teacher` ロールのユーザーのみ利用できる。生徒・保護者・管理者はアクセスできない（403）。
- 教師は、自身が実行した生徒インポートの履歴のみ、一覧・詳細・CSVエクスポートの対象にできる。他の教師が実行した履歴は、同じ学校の教師であっても参照できない（存在しない履歴として404になる）。
- 他の教師の操作を許可する権限（他職員操作権限）や担当学年による範囲制限は、本機能では判定されない。
- 問題インポートの履歴は本機能の対象外であり、参照できない。

---

# 9. 非同期処理

- なし（インポート処理自体の非同期実行と、インポートされた生徒の記録は生徒CSVインポート機能側で行われ、本機能はその結果を参照する）
