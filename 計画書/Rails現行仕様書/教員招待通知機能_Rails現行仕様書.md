# 教員招待通知機能 Rails現行仕様書

---

# 1. 機能概要

- 機能の目的
  - 新規に登録されたものの、まだ招待（パスワード設定）を完了していない教員に対して、招待メールを再送・一括送信できるようにすること。また、その送信結果の履歴を確認できるようにすること。
- システム上の役割
  - 同校の教員のうち、招待が未完了（初回パスワード未設定）の教員一覧を取得する。
  - 選択した教員に対して招待通知（招待メール）を一括送信する。
  - 送信結果（成功・失敗）の履歴を、日付で絞り込んで参照する。
- 利用者
  - `teacher` ロールのユーザー（教師）
  - 招待未完了教員一覧の取得・送信操作には、他職員操作権限（`manage_other_teachers`）が必要。送信結果履歴の参照には特別な権限は不要（同校の教師であれば閲覧できる）。

---

# 3. 業務フロー

## 招待未完了教員一覧取得・送信

1. 他職員操作権限を持つ教師が、招待未完了の教員一覧画面を表示する。
2. システムは、同校の教員のうちパスワード未設定（招待未完了）の教員一覧を返却する。
3. 教師が、通知を送りたい教員を選択して送信操作を行う。
4. システムは、選択された教員のうち実際に招待未完了の教員に対して、非同期で招待メールを送信する処理を開始する。教師には送信処理を開始した旨の応答を即座に返す。
5. （非同期処理）対象教員ごとに、招待メール（パスワード設定用リンクを含む）を送信し、送信結果（成功・失敗）を送信履歴として記録する。

## 送信結果履歴取得

1. 教師が送信結果履歴画面を表示する。
2. 必要に応じて日付を指定して絞り込む。
3. システムは、同校の教員宛てに送信された招待通知の履歴を、送信日時の新しい順に返却する。

# 5. API / 処理詳細

## `Api::V1::Teacher::TeacherNotificationsController#index`

### 概要

同校の教員のうち、招待（初回パスワード設定）が完了していない教員の一覧を取得する。

### Request

なし

### 処理内容

1. 教師の所属高校に属する教員ロールのユーザーのうち、パスワード未設定（招待未完了）状態のものを取得する。
2. `Teacher::UnsentTeacherSerializer` で返却する。

### 業務ルール

- 同校の教員のみ対象とする。
- 「招待未完了」とは、初回ログイン用の仮パスワードが設定されたまま、まだパスワードが再設定されていない状態を指す。

### Database変更

- なし

### Response

- 招待未完了の教員一覧（`id`, `name`, `name_kana`, `email`）

### Errorケース

- なし（他職員操作権限を持つ教師であることが前提）

## `Api::V1::Teacher::TeacherNotificationsController#create`

### 概要

選択した教員に対して、招待通知（招待メール）を一括送信する。

### Request

|項目|必須|型|説明|
|-|-|-|-|
|`teacher_ids[]`|任意|array of integer|通知を送信する教員の ID の配列|

### 処理内容

1. 操作する教師が「他職員操作権限」を持っているか確認する。権限がない場合は `403 Forbidden` を返却する。
2. 同校の教員のうち招待未完了の教員に絞り込んだうえで、指定された `teacher_ids` に一致する教員のみを送信対象として確定する（同校でない教員、既に招待完了済みの教員は指定されても送信対象から除外される）。
3. 送信対象の教員IDを引数に、招待通知を送信する非同期ジョブを起動する。
4. `202 Accepted` で「送信処理を開始しました」という受付完了の応答を返す（この時点では送信は完了していない）。
5. （非同期ジョブ内）対象教員ごとに、パスワード再設定用のトークンを発行し、招待メールを送信する。
6. （非同期ジョブ内）送信に成功した場合は「成功（`sent`）」、失敗した場合は「失敗（`failed`）」として、送信結果を送信通知履歴に記録する。

### 業務ルール

- この操作は「他職員操作権限」を持つ教師のみ実行できる。
- 送信対象は、同校に所属し、かつ招待未完了の教員に限られる。他校の教員や既に招待完了済みの教員のIDが指定されても、送信対象からは除外される。
- `teacher_ids` が空、または対象が0件でも、送信処理自体はエラーにはならず受け付けられる（実際に送信される教員が0人になるのみ）。
- 1人の教員へのメール送信が失敗しても、他の対象教員への送信処理は継続される（1件ごとに成功・失敗が記録される）。

### Database変更

作成（非同期ジョブ実行後、対象教員ごとに1件）:

```
teacher_notifications
```

### Response

- `message`: `送信処理を開始しました`

### Errorケース

|条件|HTTP Status|内容|
|-|-|-|
|他職員操作権限がない|403|`他教員を招待する権限がありません`|

## `Api::V1::Teacher::TeacherNotificationResultsController#index`

### 概要

同校の教員宛てに送信された招待通知の結果履歴を取得する。

### Request

|項目|必須|型|説明|
|-|-|-|-|
|`sent_at`|任意|date|指定した日付に送信されたものだけに絞り込む|

### 処理内容

1. 送信者が同校に所属する教員である招待通知を対象とする。
2. `sent_at` が指定された場合、その日付（当日0時〜24時）に送信されたものに絞り込む。
3. 送信日時の新しい順に並べる。
4. `Teacher::TeacherNotificationSerializer` で返却する。

### 業務ルール

- 送信者（送信操作を行った教師）が同校である通知履歴のみが対象。
- 日付指定時は、その日一日分（0時から24時まで）の送信結果に絞り込まれる。

### Database変更

- なし

### Response

- 送信結果一覧。各件は `id`, `email`（送信先メールアドレス）, `status`（`pending`/`sent`/`failed`）, `formatted_sent_at`（`YYYY/MM/DD HH:MM`形式の送信日時）, 送信者（`id`, `name`）, 送信先教員（`id`, `name`）を含む

### Errorケース

- なし（認証前提）

# 6. データモデル

## `teacher_notifications`

- 役割: 教員への招待通知の送信結果を1件ごとに記録するテーブル
- 主なカラム: `id`, `sender_user_id`（送信操作を行った教師）, `receiver_user_id`（送信先教員）, `email`（送信先メールアドレス）, `sent_at`（送信日時）, `status`（`pending`/`sent`/`failed`）
- リレーション: `belongs_to :sender_user`（送信者ユーザー）, `belongs_to :receiver_user`（受信者ユーザー）

---

# 7. 状態管理

```
pending（未送信）
  ↓                          ↓
sent（送信成功）         failed（送信失敗）
```

状態変更条件:

- 招待通知は、非同期ジョブによる送信処理の実行結果として、成功時は「送信成功」、失敗時は「送信失敗」のいずれかの状態で作成される。「未送信」はレコード上のデフォルト値であり、通常のフローでは作成と同時に成功・失敗いずれかの状態が記録される。

---

# 8. 権限制御

- 招待未完了教員一覧の取得、招待通知の一括送信は、いずれも「他職員操作権限」を持つ教師のみが行える。
- 送信結果履歴の取得には、他職員操作権限は不要で、同校の教師であれば誰でも閲覧できる。ただし対象は自校の教員宛ての送信結果に限られる。
- 招待通知の送信対象は、常に操作する教師の所属高校に属する教員に限定される。

---

# 9. 非同期処理

- `Teacher::TeacherNotificationJob`：`create`アクションから起動され、送信者の教師IDと送信対象の教員ID一覧を受け取る。対象教員ごとにパスワード再設定用トークンを発行して招待メールを送信し、成功・失敗いずれの場合も送信結果を`teacher_notifications`に記録する。1人の送信に失敗しても、他の対象者への送信処理には影響しない。
