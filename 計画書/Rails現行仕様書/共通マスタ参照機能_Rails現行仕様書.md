# 共通マスタ参照機能 Rails現行仕様書

---

# 1. 機能概要

- 機能の目的
  - 会員登録・プロフィール編集・生徒登録などの入力フォームが選択肢として必要とする共通マスタ（都道府県・住所・在籍高校・学年）を参照できるようにすること。
- システム上の役割
  - 参照専用の機能である。マスタの登録・更新・削除を行う操作はこの機能に含まれない。
  - 都道府県 → 住所、都道府県 → 高校 → 学年という段階的な絞り込みを前提とし、前段で選んだ値を条件として次の候補を返す。
- 利用者
  - 都道府県一覧・高校検索・学年一覧は**未認証でも利用できる**。会員登録フォームが利用するためである。
  - 住所検索のみ認証が必要で、ロールは問わない。

---

# 2. 機能一覧

|操作|概要|認証|
|-|-|-|
|都道府県一覧取得|都道府県を全件取得する|不要|
|住所検索|都道府県を必須条件とし、市区町村・町域で絞り込んで住所を取得する|必要|
|高校検索|都道府県を条件とし、名称で絞り込んで在籍高校を取得する|不要|
|学年一覧取得|指定した高校に属する学年を取得する|不要|

---

# 3. 業務フロー

## 会員登録フォームでの利用（都道府県 → 高校 → 学年）

1. 利用者が登録フォームを開く。
2. システムは都道府県を全件返す。
3. 利用者が都道府県を選ぶ。
4. システムはその都道府県の高校を、名称の一部で絞り込みながら返す。
5. 利用者が高校を選ぶ。
6. システムはその高校に属する学年を返す。
7. 利用者が学年を選ぶ。

## 住所入力での利用（都道府県 → 市区町村 → 町域）

1. 利用者が住所入力を開く。
2. システムは都道府県を全件返す。
3. 利用者が都道府県を選ぶ。都道府県を選ばないまま住所を要求した場合はエラーとして返す。
4. 利用者が市区町村・町域の一部を入力する。
5. システムは入力された文字を含む住所を返す。

# 5. API / 処理詳細

## `Api::V1::PrefecturesController#index`

### 概要

都道府県を全件返す。入力フォームの最初の選択肢として使われる。

### Request

パラメータなし。

### 処理内容

1. 都道府県を全件取得する。
2. 識別子と名称だけを返す。

### 業務ルール

- 認証を必要としない。会員登録フォームから呼ばれるためである。
- 絞り込み・ページネーション・並び順の指定を行わない。件数が固定（47件）であることを前提としている。

### Database変更

- なし

### Response

HTTP Status は `200`。最上位はJSON配列。

|項目|型|説明|
|-|-|-|
|`[].id`|integer|都道府県の識別子|
|`[].name`|string|都道府県名|

### Errorケース

|条件|HTTP Status|内容|
|-|-|-|
|なし|-|入力を受け取らないため、業務上のエラーが発生しない|

## `Api::V1::AddressesController#index`

### 概要

都道府県を必須条件とし、市区町村・町域で絞り込んで住所を返す。

### Request

|項目|必須|型|説明|
|-|-|-|-|
|`prefecture_id`|必須|integer|都道府県の識別子|
|`city`|任意|string|市区町村名の一部|
|`town`|任意|string|町域名の一部|

### 処理内容

1. `prefecture_id` が未指定または空文字の場合、エラーを返して処理を終える。
2. 都道府県で絞り込む。
3. `city` が指定されていれば、市区町村名に対する部分一致で絞り込む。
4. `town` が指定されていれば、町域名に対する部分一致で絞り込む。
5. 住所と、それが属する都道府県の情報を返す。

### 業務ルール

- **認証が必要である。** ロールは問わない。他の3操作と異なり未認証では利用できない。
- `prefecture_id` は必須。指定がない場合は検索を行わない。住所の全件を返さないための制約である。
- `city`・`town` はいずれも部分一致で絞り込む。前方一致・完全一致ではない。
- 空文字は未指定として扱い、絞り込みに使わない。
- 論理削除済みの住所（`deleted_at` が設定されたもの）を**除外しない。**
- 並び順の指定を行わない。ページネーションも行わない。該当件数が多い場合も全件返す。
- 該当する住所がない場合は空の配列を返す。エラーにしない。

### Database変更

- なし

### Response

HTTP Status は `200`。最上位はJSON配列。

|項目|型|説明|
|-|-|-|
|`[].id`|integer|住所の識別子|
|`[].postal_code`|string|郵便番号|
|`[].city`|string|市区町村名|
|`[].town`|string / null|町域名|
|`[].prefecture`|object / null|都道府県。住所に都道府県が紐づいていない場合は `null`|
|`[].prefecture.id`|integer|都道府県の識別子|
|`[].prefecture.name`|string|都道府県名|

番地（`street_address`）は返さない。

### Errorケース

|条件|HTTP Status|内容|
|-|-|-|
|`prefecture_id` が未指定または空文字|400|`{"errors": ["都道府県は必須です。"]}`|
|未認証|401|認証されていない|

## `Api::V1::HighSchoolsController#index`

### 概要

都道府県を条件とし、名称で絞り込んで在籍高校を返す。

### Request

|項目|必須|型|説明|
|-|-|-|-|
|`prefecture_id`|必須|integer|都道府県の識別子。指定しなければ結果が得られない（業務ルールを参照）|
|`keyword`|任意|string|高校名の一部|

### 処理内容

1. 高校の全件を起点に、`prefecture_id` で絞り込む。
2. `keyword` が指定されていれば、高校名に対する部分一致で絞り込む。
3. 高校名の昇順に並べ、先頭20件に限って返す。

### 業務ルール

- 認証を必要としない。会員登録フォームから呼ばれるためである。
- **都道府県の指定を必須とする仕様である。** `prefecture_id` の絞り込みは、指定がない場合も条件として適用される。`high_schools.prefecture_id` は未設定を許さないカラムであるため、指定しないと該当する高校が0件となり空の配列が返る。高校の全件を返さないための制約であり、住所検索が `prefecture_id` を必須として `400` を返すのと同じ意図である。高校検索では `400` を返さず空の配列を返す点が住所検索と異なる。
- `keyword` は部分一致で絞り込む。空文字・未指定の場合は絞り込みに使わない。
- 並び順は高校名の昇順。
- **返す件数は最大20件。** 21件目以降は返さない。ページネーションの手段はなく、残りを取得できない。絞り込みを増やして件数を減らすことが前提になっている。
- 該当する高校がない場合は空の配列を返す。エラーにしない。

### Database変更

- なし

### Response

HTTP Status は `200`。最上位はJSON配列。

|項目|型|説明|
|-|-|-|
|`[].id`|integer|高校の識別子|
|`[].name`|string|高校名|
|`[].csv_managed`|boolean|生徒をCSVインポートで管理する高校かどうか|

都道府県・学校コードは返さない。

### Errorケース

|条件|HTTP Status|内容|
|-|-|-|
|該当なし|200|空の配列を返す。エラーにしない|

### 実装のないアクションへの経路

ルーティングがアクションを絞っていないため、この機能が実装していないアクションへの経路が存在する。

|経路|結果|
|-|-|
|`GET /api/v1/high_schools/:id`|`show` アクションが存在せず、例外になる|
|`POST /api/v1/high_schools`|`create` アクションが存在せず、例外になる|
|`PATCH` / `PUT` / `DELETE /api/v1/high_schools/:id`|同様|

高校の登録・更新・削除はこの機能に含まれず、他の機能にも実装されていない。高校のレコードが作成される際は学校コード（`school_code`）が自動発行されるが、その経路はAPIとしては提供されていない。

## `Api::V1::GradesController#index`

### 概要

指定した高校に属する学年を返す。

### Request

|項目|必須|型|説明|
|-|-|-|-|
|`high_school_id`|必須|integer|高校の識別子。パスに含まれる|

### 処理内容

1. 指定された高校の識別子で学年を絞り込む。
2. 識別子・年次・表示名を返す。

### 業務ルール

- 認証を必要としない。会員登録フォームから呼ばれるためである。
- **高校の実在確認を行わない。** 存在しない識別子を指定した場合も、該当する学年が0件となり空の配列が返る。`404` にはならない。
- 並び順の指定を行わない。年次の昇順になる保証はない。
- ページネーションを行わない。
- 表示名は年次から導出する。対応は次のとおり。

|年次|表示名|
|-|-|
|0|中３生|
|1|高１生|
|2|高２生|
|3|高３生|
|4|高卒生|
|5|新高１生|
|6|新高２生|
|7|新高３生|
|上記以外|不明|

### Database変更

- なし

### Response

HTTP Status は `200`。最上位はJSON配列。

|項目|型|説明|
|-|-|-|
|`[].id`|integer|学年の識別子|
|`[].year`|integer|年次|
|`[].display_name`|string|年次に対応する表示名|

所属高校の識別子は返さない。

### Errorケース

|条件|HTTP Status|内容|
|-|-|-|
|存在しない高校の識別子|200|空の配列を返す。`404` にはならない|

# 6. データモデル

|テーブル|役割|主なカラム|
|-|-|-|
|`prefectures`|都道府県マスタ|`id`, `name`|
|`addresses`|住所マスタ|`id`, `postal_code`, `city`, `town`, `street_address`, `prefecture_id`, `deleted_at`|
|`high_schools`|在籍高校マスタ|`id`, `name`, `prefecture_id`, `school_code`, `csv_managed`|
|`grades`|学年マスタ|`id`, `high_school_id`, `year`|

リレーション:

- `prefectures` は複数の `addresses` と複数の `high_schools` を持つ。
- `addresses.prefecture_id` は**未設定を許す。** そのため住所に都道府県が紐づいていない行が存在しうる。
- `high_schools.prefecture_id` は未設定を許さない。
- `high_schools` は複数の `grades` を持つ。`grades.high_school_id` は未設定を許さない。
- `grades.year` は同じ高校の中で重複できない。
- `addresses`・`high_schools` はいずれも `users` から参照される。`grades` は `users`・`school_classes`・`teacher_grades` から参照される。

論理削除の扱い:

- 論理削除の列（`deleted_at`）を持つのは `addresses` のみである。`prefectures`・`high_schools`・`grades` は持たない。
- `addresses` に対する既定の絞り込みは定義されておらず、住所検索は論理削除済みの行も返す。

学校コード（`school_code`）:

- 高校のレコードが作成されるときに、未設定であれば自動で発行される。英数字6桁の大文字で、既存のコードと重複しないものが選ばれる。
- 一意制約がある。未設定は許される。
- 生徒番号の発行（生徒CSVインポート機能・認証機能）で、高校を特定する手がかりとして使われる。
- この機能のレスポンスには含まれない。

# 7. 状態管理

- なし。この機能が扱う4つのマスタは、いずれも状態を表すカラムを持たない。
- `csv_managed` は高校の属性であり、生徒の登録方法（CSVインポートで管理するか）を表す区分である。状態遷移を持つものではない。

# 8. 権限制御

|操作|認証|ロール|
|-|-|-|
|都道府県一覧取得|不要|-|
|住所検索|必要|問わない|
|高校検索|不要|-|
|学年一覧取得|不要|-|

- 都道府県一覧・高校検索・学年一覧は、会員登録フォームから呼ばれるため認証を行わない。登録前の利用者がアクセスできる必要がある。
- 住所検索のみ認証が必要である。他の3操作は会員登録フォームが登録前に呼ぶため認証を外しているが、住所検索を使うのはログイン後のプロフィール編集画面であり、登録前に呼ばれることがない。認証を外す必要がないため既定の認証がそのまま適用されている。
- いずれの操作もロールによる制限を行わない。操作者によって結果が変わることもない。
- 高校の登録・更新・削除の経路はルーティング上存在するが、アクションが実装されていないため利用できない（「5. API / 処理詳細」の「実装のないアクションへの経路」）。

---

# 9. 非同期処理

- なし。参照はすべてリクエスト時に同期で実行される。
- キャッシュ・事前集計も使用していない。都道府県のように更新されないマスタも都度取得している。
