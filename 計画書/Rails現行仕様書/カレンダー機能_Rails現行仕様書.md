# カレンダー機能 Rails現行仕様書

---

# 1. 機能概要

生徒が、自分の学習予定と面談予定を1つのカレンダー上でまとめて確認できるようにする機能である。

指定した期間に含まれる次の3種類の予定を、1回の取得で日付順に受け取る。

|種別|日付として扱うもの|
|-|-|
|目標|目標の期限日|
|タスク|タスクの期限日|
|面談|確定した面談日時の日付|

システム上の役割は、目標・タスク・面談という別々に管理されている情報を、**日付という観点で1つの時系列にまとめて提供すること**である。予定の作成・変更・削除は行わず、参照のみを提供する。

利用者は生徒である。教員向けのカレンダー表示は本機能を使わず、教師面談機能の面談一覧に期間を指定して取得する（教師面談機能①「5. API / 処理詳細」`#index`）。期間指定の検証規則は両者で共通である。

|操作|概要|

|期間指定の予定取得|指定した期間に含まれる目標・タスク・面談を、日付順に並べた1つの配列として取得する|

---

# 3. 業務フロー

1. 生徒がカレンダー画面を開く。画面は表示中の月のカレンダーの升目が覆う範囲（前月末・翌月初を含む）を期間として指定する。
2. システムは期間の指定（開始日・終了日）を検証する。
3. 期間内に期限日がある自分の目標を取得する。
4. 期間内に期限日がある自分のタスクを取得する。
5. 期間内に面談日時がある自分の面談を取得する。取り消し済みの面談は除く。
6. 3つの結果を1つの配列にまとめ、日付・種別・識別子の順に並べる。
7. 日付を表示用の形式に変換して返却する。

# 5. API / 処理詳細

## `Api::V1::Student::CalendarsController#show`

### 概要

ログイン中の生徒について、指定した期間に含まれる目標・タスク・面談を1つの配列で取得する。

### Request

|項目|必須|型|説明|
|-|-|-|-|
|`from`|必須|string|取得期間の開始日（`YYYY-MM-DD`）|
|`to`|必須|string|取得期間の終了日（`YYYY-MM-DD`）|

### 処理内容

1. `from` と `to` を検証する。両方が必須であり、`YYYY-MM-DD` 形式の実在する日付で、`from` が `to` 以前で、期間が 92 日以内でなければならない。
2. 自分の目標のうち、期限日が `from` から `to` までに入るものを取得する。
3. 自分のタスクのうち、期限日が `from` から `to` までに入るものを取得する。
4. 自分が当事者である面談のうち、面談日時が `from` の 0 時から `to` の 24 時までに入るものを取得する。取り消し済み（`cancelled`）は除外する。
5. 3種類の結果を1つの配列にまとめ、日付の昇順、同じ日付では種別の名前の昇順（`goal` → `interview_request` → `task`）、さらに同じ種別では識別子の昇順に並べる。
6. 各要素の日付を `YYYY/MM/DD` 形式の文字列に変換して返却する。

### 業務ルール

- 自分の目標・タスク・面談のみが対象となる。他の生徒の予定は含まれない。
- `from` と `to` はいずれも必須である。片方だけの指定は受け付けない。
- 期間は 92 日以内で指定する。両端を含めて 92 日までが許容される。
- **論理削除済みの目標・タスクは対象外である。** 目標・タスクはいずれも既定で論理削除済みを除外して参照される。
- **取り消し済みの面談は対象外である。** 申請中・調整中・確定済み・完了の面談は、面談日時が設定されていれば対象となる。
- **面談日時が設定されていない面談は対象外である。** 面談日時は教員による確定操作で設定されるため、申請中・調整中の面談は期間の条件を満たさず返らない（面談機能①「7. 状態管理」）。
- 目標・タスクは期限日（日付）、面談は面談日時（日時）という異なる粒度の項目を日付として扱う。面談は日時の日付部分を取り出して返す。
- 1件も該当しない場合は空の配列を返す。エラーにはしない。

### Database変更

- なし

### Response

- **200 OK**
- 予定の配列。各要素は次の項目を持つ。

|項目|型|説明|
|-|-|-|
|`type`|string|予定の種別。`goal` / `task` / `interview_request`|
|`id`|integer|種別ごとの識別子（目標ID・タスクID・面談ID）|
|`date`|string|日付（`YYYY/MM/DD`）|
|`title`|string|表示名。目標・タスクは件名、面談は相談理由の詳細|
|`status`|string|状態。目標・タスクは `not_started` / `in_progress` / `completed`、面談は `requested` / `scheduling` / `confirmed` / `completed`|

最上位はオブジェクトで包まず、配列をそのまま返す。

`type` と `id` の組で初めて一意になる。目標・タスク・面談は別のテーブルであり、識別子が重複しうる。

### Errorケース

エラー本文は `{"errors": [メッセージ, ...]}` の形式で、複数のメッセージが同時に含まれうる。

|条件|HTTP Status|内容|
|-|-|-|
|`from` が未指定|422|`From を入力してください`|
|`to` が未指定|422|`To を入力してください`|
|`from` が `YYYY-MM-DD` 形式でない、または存在しない日付|422|`From は正しい日付を入力してください`|
|`to` が `YYYY-MM-DD` 形式でない、または存在しない日付|422|`To は正しい日付を入力してください`|
|`from` が `to` より後|422|`To はfrom以降の日付を指定してください`|
|期間が 92 日を超える|422|`取得期間は92日以内で指定してください`|
|未認証|401|認証されていない|
|`student` ロール以外|403|`{"errors": ["この操作を行う権限がありません"]}`|

メッセージ先頭の `From` / `To` は、項目名の日本語訳が定義されていないため、項目名がそのまま英語表記で出力されている。

# 6. データモデル

本機能は専用のテーブルを持たない。次の3つのテーブルを参照する。

## `goals`

- 役割: 生徒の学習目標を記録するテーブル。
- 本機能が参照する主なカラム:
  - `id`
  - `user_id`（所有する生徒）
  - `title`（件名。`title` を表示名として返す）
  - `due_date`（期限日。期間の判定に使う）
  - `status`（`not_started` / `in_progress` / `completed`）
  - `deleted_at`（論理削除。既定で論理削除済みを除外して参照される）
- リレーション: `belongs_to :user`、`has_many :tasks`

## `tasks`

- 役割: 生徒の学習タスクを記録するテーブル。
- 本機能が参照する主なカラム:
  - `id`
  - `user_id`（所有する生徒）
  - `title`（件名。表示名として返す）
  - `due_date`（期限日。期間の判定に使う）
  - `status`（`not_started` / `in_progress` / `completed`）
  - `deleted_at`（論理削除。既定で論理削除済みを除外して参照される）
- リレーション: `belongs_to :user`、`belongs_to :goal`

## `interview_requests`

- 役割: 生徒と教員の面談申請・実施状況を記録するテーブル。
- 本機能が参照する主なカラム:
  - `id`
  - `student_id` / `teacher_id`（当事者）
  - `reason_detail`（相談理由の詳細。表示名として返す）
  - `scheduled_at`（確定した面談日時。期間の判定に使い、日付部分を返す）
  - `status`（`requested` / `scheduling` / `confirmed` / `completed` / `cancelled`）
- リレーション: `belongs_to :student`（`User`）、`belongs_to :teacher`（`User`）

テーブルの全体像は目標管理機能①・タスク管理機能①・面談機能①の「6. データモデル」を参照する。

# 7. 状態管理

本機能は状態を持たず、状態を変更しない。

返却する `status` は、参照した目標・タスク・面談それぞれの状態をそのまま載せたものである。状態の遷移条件は各機能①の「7. 状態管理」に属する。

本機能が状態に関して持つ唯一の規則は、**取り消し済みの面談を除外すること**である。目標・タスクは状態による除外を行わず、完了済みのものも返す。

---

# 8. 権限制御

|項目|内容|
|-|-|
|利用可能ユーザー|`student` ロールのユーザーのみ。認証必須|
|閲覧制限|自分が所有する目標・タスク、および自分が当事者である面談のみ|
|操作制限|参照のみ。作成・更新・削除の操作を持たない|

生徒以外のロールは、生徒向けAPI共通の認可で拒否される（403）。閲覧範囲は、目標・タスクはログイン中のユーザーに紐づくもの、面談は当事者であるものに限られ、他の生徒の予定が混ざることはない。

---

# 9. 非同期処理

なし。本機能は参照のみであり、ジョブ・メール送信を伴わない。

# 確認できない事項

- **`title` に文字数の上限や表示用の加工がない。** 目標・タスクの件名、面談の相談理由の詳細をそのまま返しており、相談理由の詳細は 2000 文字まで登録できる（面談機能①「5. API / 処理詳細」`#create`）。カレンダーの表示側で切り詰めるかどうかは画面側の扱いであり、API仕様としては制限がない。
- **期間の上限 92 日の由来。** 実装上の定数として定義されているのみで、業務上の根拠は確認できない。カレンダー画面が1か月分の升目（最大 42 日）を要求するため、現在の画面利用では上限に達しない。
