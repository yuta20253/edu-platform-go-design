# プロフィール管理機能 Rails現行仕様書

---

# 1. 機能概要

- 機能の目的
  - ログイン中のユーザーが、自分自身の基本情報（氏名）、個人情報（電話番号・生年月日・性別）、住所を確認・更新できるようにする。
- システム上の役割
  - ログイン中ユーザー自身の登録情報（基本情報・個人情報・住所・所属高校・学年など）をまとめて取得する。
  - 氏名・個人情報・住所を一括で検証し、更新する。
  - 個人情報・住所がすべて登録済みかどうかを判定し、プロフィール登録が完了しているかを表す状態を提供する。
- 利用者
  - ログイン中の `student` / `teacher` / `admin` ロールのユーザー（自分自身の情報のみ操作可能）

補足として、ログイン直後や新規登録直後のレスポンスにもユーザー情報が含まれるが、これらは「認証機能」で提供される。本機能は、ログイン後に改めて自身の情報を参照・更新する操作を扱う。

---

# 2. 機能一覧

|操作|概要|
|-|-|
|プロフィール参照|ログイン中ユーザー自身の登録情報を取得する|
|プロフィール更新|氏名・個人情報・住所をまとめて更新する|

# 3. 業務フロー

## プロフィール参照

1. ユーザーがログイン中の状態でプロフィール参照を要求する。
2. システムは Cookie の JWT からユーザーを特定する。
3. ユーザー本人の基本情報・個人情報・ロール・所属高校・住所（都道府県含む）・学年をまとめて取得する。
4. 取得した情報を返却する。

## プロフィール更新

1. ユーザーが氏名・氏名カナ・住所ID・生年月日・性別・電話番号を送信する。
2. システムは入力値を検証する。
   - 氏名・氏名カナは必須で、氏名カナはカタカナ形式であること。
   - 電話番号は入力する場合10〜11桁の数字であること。
   - 性別は定義された選択肢（男性・女性・その他）のいずれかであること。
   - 住所IDを指定する場合、存在する住所であること。
   - 生年月日を指定する場合、未来日でないこと。
3. 検証に成功した場合、ユーザーの基本情報（氏名・氏名カナ・住所）と、個人情報（電話番号・生年月日・性別）を同一トランザクションで更新する。個人情報が未登録の場合は新規に作成する。
4. 更新後のユーザー情報を返却する。
5. 検証に失敗した場合は更新を行わず、エラー内容を返却する。

# 4. API一覧

|Controller|Action|HTTP Method|Endpoint|概要|
|-|-|-|-|-|
|`Api::V1::UsersController`|`show`|GET|`/api/v1/me`|ログイン中ユーザー自身の情報を取得|
|`Api::V1::ProfilesController`|`update`|PATCH|`/api/v1/profile`|ログイン中ユーザー自身の基本情報・個人情報・住所を更新|

`GET /api/v1/me` は「認証機能」ではログイン中ユーザー情報取得として説明されており、同一のエンドポイントである。本機能ではプロフィール参照の入口として位置づける。

# 5. API / 処理詳細

## `Api::V1::UsersController#show`

### 概要

ログイン中のユーザー自身の基本情報・個人情報・所属高校・住所・学年をまとめて取得する。プロフィール編集画面を開いた際の初期表示などに利用される。

### Request

- パラメータなし（Cookie の JWT から対象ユーザーを特定する）

### 処理内容

1. Cookie の JWT から認証済みユーザーを特定する。
2. 個人情報・ロール・所属高校・住所（都道府県含む）をまとめて取得する。
3. ユーザー情報を返却する。

### 業務ルール

- 本人の情報のみ取得可能であり、他ユーザーの情報は取得できない。

### Response

- 200 OK
- `user`:
  - `id`, `name`, `name_kana`, `email`, `profile_completed`
  - `user_personal_info`（`phone_number`, `birthday`, `gender` など）
  - `user_role`, `high_school`, `address`（都道府県含む）, `grade`

### Errorケース

|条件|HTTP Status|内容|
|-|-|-|
|未ログイン|401|認証エラー|

---

## `Api::V1::ProfilesController#update`

### 概要

ログイン中のユーザー自身の氏名・個人情報・住所をまとめて更新する。

### Request

|項目|必須|型|説明|
|-|-|-|-|
|name|任意|string|氏名|
|name_kana|任意|string|氏名カナ。指定する場合はカタカナ形式であること|
|address_id|任意|integer|住所ID。存在する住所であること|
|birthday|任意|date|生年月日。未来日は不可|
|gender|任意|string|性別。`male` / `female` / `other` のいずれか|
|phone_number|任意|string|電話番号。指定する場合は10〜11桁の数字|

### 処理内容

1. リクエストパラメータとログイン中ユーザーを合わせて `ProfileUpdateForm` に渡し、入力値を検証する。
2. 検証に成功した場合、ユーザーの `name`, `name_kana`, `address_id` を更新する。
3. 個人情報（`user_personal_info`）が存在しない場合は新規に作成し、`phone_number`, `birthday`, `gender` を更新する。
4. 上記2・3は同一トランザクションで実行され、いずれかが失敗した場合は更新全体が取り消される。
5. 更新後のユーザー情報を返却する。

### 業務ルール

- 本人の情報のみ更新可能であり、他ユーザーの情報は更新できない。
- 氏名カナはカタカナ・長音符・中黒・空白のみで構成されている必要がある。
- 電話番号は未入力を許容するが、入力する場合は10〜11桁の数字である必要がある。
- 性別は `UserPersonalInfo` に定義された選択肢（`male` / `female` / `other`）以外は指定できない。
- 住所IDを指定する場合、`addresses` テーブルに存在するIDである必要がある。
- 生年月日は未来日を指定できない。
- 氏名・個人情報・住所の更新は一括で行われ、一部項目のみを更新することはできない（未指定の項目は空値として更新される）。

### Database変更

更新:

```
users
user_personal_infos
```

### Response

- 200 OK
- `user`:
  - `id`, `name`, `name_kana`, `email`, `profile_completed`
  - `user_personal_info`, `user_role`, `high_school`, `address`, `grade`

### Errorケース

|条件|HTTP Status|内容|
|-|-|-|
|入力値検証エラー（氏名未入力、氏名カナ形式不正、電話番号形式不正、性別不正、住所ID不正、生年月日が未来日など）|422|エラーメッセージ一覧|

# 6. データモデル

## `users`

- 役割: ユーザーの基本情報を保持する。
- 主なカラム: `name`, `name_kana`, `address_id`
- リレーション: `belongs_to :address`, `has_one :user_personal_info`

## `user_personal_infos`

- 役割: ユーザーの個人情報を保持する。
- 主なカラム: `user_id`, `phone_number`, `birthday`, `gender`
- リレーション: `belongs_to :user`
- `gender` は `male` / `female` / `other` の値を持つ区分値として管理される。

## `addresses`

- 役割: ユーザーが選択する住所情報を保持する。
- 主なカラム: `postal_code`, `city`, `town`, `street_address`, `prefecture_id`
- リレーション: `belongs_to :prefecture`, `has_many :users`
- 住所の一覧取得・検索の仕様は「共通マスタ参照機能」を参照。

---

# 7. 状態管理

ユーザーのプロフィール登録が完了しているかどうかは、以下の項目がすべて登録されているかによって判定される（専用のステータスカラムを持つわけではなく、都度計算される）。

```
未完了

↓（住所・電話番号・生年月日・性別がすべて登録される）

完了
```

状態変更条件:

- 住所（`address_id`）、個人情報の電話番号・生年月日・性別のいずれかが未登録の場合は「未完了」と判定される。
- 上記すべてが登録されると「完了」と判定される。
- この状態はレスポンスの `profile_completed` としてユーザー情報取得時に都度返却される。

---

# 8. 権限制御

- `UsersController#show` / `ProfilesController#update` はいずれも認証必須であり、未ログインの場合は401エラーとなる。
- 操作対象は常にログイン中の本人であり、他ユーザーのプロフィールを参照・更新するAPIではない。
- ロールによる操作制限はなく、`student` / `teacher` / `admin` いずれのユーザーも自分自身のプロフィールを参照・更新できる。

---

# 9. 非同期処理

確認できない事項（本機能に関連するJob・Mailerは存在しない）。
